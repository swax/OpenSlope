# Unity

**OpenSlope's Unity importer and ride runtime for Unity, Basis, and VRChat.** This library turns a staged
`Maps/<MAP>/` folder into a rideable scene with terrain, props, collision, lighting, audio, effects,
and board-based traversal. Authored and imported maps use the same bundle contract.

This folder is source code, not a package generated by Snowknife. Copy it into a Unity project; the
core importer targets Unity's built-in render pipeline, while the VRChat runtime requires the VRChat
SDK and UdonSharp.

## Setup

1. Create or open a built-in-render-pipeline project in Unity **2022.3.22f1**.
2. Add `com.unity.nuget.newtonsoft-json`.
3. For VRChat, install the VRChat SDK and UdonSharp.
4. Copy `Importer/` and `VRC/` into the project's `Assets/` folder.
5. Build and stage a map with [Snowknife](../Snowknife/README.md):

   ```powershell
   snowknife gltf  Maps\MYMAP MYMAP
   snowknife unity Maps\MYMAP C:\MyWorld\Assets\OpenSlope\Maps\MYMAP
   ```

   Retail-derived projects may also need `snowknife shared <iso> Maps\Shared`; ordinary `unity`
   staging copies that Shared sibling automatically. Public projects must instead follow the
   [public path](#public-and-private-projects).

## Import and test

In Unity:

1. Run **OpenSlope → Load → Map…** and select `Assets/OpenSlope/Maps/<MAP>`.
2. Run **OpenSlope → Setup All**. Keep Unity focused while its final probe bake runs.
3. Optionally run **OpenSlope → Setup → Surface Audio** for on-foot material footsteps; this is intentionally
   not part of Setup All.
4. Enter Play mode with ClientSim or build the world.

On a fresh project, Load and Setup All may each stop after creating UdonSharp program assets. Let Unity
compile, then run that command once more. Re-run Setup All after every full map import because the import
replaces the `OpenSlope_Map` root and its post-import runtime objects.

Setup All handles the normal VRChat scene pass: static chunking, teleports, locomotion, music, player
flight, board dispensers, race audio, video/score/info boards, leaderboard and finish line, HUD,
performance and tuning controls, optional map snowfall, and avatar-light probes. Individual commands
remain available for focused iteration.

| Menu | Use |
|---|---|
| **Load** | Import a complete staged map |
| **Setup All** | Run the standard post-import VRChat setup and probe bake |
| **Setup** | Run one post-import system, listed in the order Setup All runs them; includes opt-in Surface Audio |
| **Refresh** | Rebuild one imported subsystem without a full import |
| **Optimize** | Re-run scene optimization such as static chunking and draw-call batching |
| **Tools** | Scene and asset utilities, analyzers, and debug windows |
| **Dev** | Importer development: partial gltf bundle loads and the ClientSim autotest |

A system that is built by find-or-create has ONE entry, under **Setup** — re-running it is the refresh
(the boards, the HUD, the Jukebox). **Refresh** is only for subsystems rebuilt from the bundle.

Menu order is set by `MenuItem` priority bands, not by hand-picked numbers: each group starts at a
multiple of 20 and each item inside it is the next `+1` (Setup 110/130/150/170/190/210, Refresh
300/320/340, Optimize 500, Tools 700/720/740, Dev 900/920). Unity draws a separator wherever
consecutive priorities differ by 11 or more, so the bands are what produce the grouping. When adding an
item, take the next free number in its band; never reuse one, because tied priorities fall back to
assembly registration order and shuffle on recompile.

The ClientSim automation contract and runner are documented in
[VRChat autotest](docs/vrchat/055-clientsim-autotest.md).

## What is here

| Path | Owns |
|---|---|
| `Importer/` | Engine-neutral Unity editor importer and bundle readers |
| `VRC/` | VRChat/Udon runtime, shaders, setup commands, and platform wiring |
| `Basis/` | Basis realization of the same imported marker contracts |
| `docs/` | Importer, runtime, Basis, and authoring design documents |
| `tools/` | Source sync, boundary checks, Unity/ClientSim tests, and built-world diagnostics |

The importer builds one `OpenSlope_Map` root from Snowknife's glTF files and `manifest.json`. It handles
geometry, materials, lightmaps, collision, rails, effects, particles, audio placement, and probe
positions without reinterpreting retail formats. Platform wiring then realizes neutral markers as
VRChat or Basis behaviors. See the [documentation index](docs/README.md) and Snowknife's
[bundle pipeline](../Snowknife/docs/034-bundle-pipeline.md).

## Keeping project copies in sync

This folder is the source of truth. Do not edit only the copy inside a Unity project. To update a
project and report changed `.cs` and `.shader` files:

```powershell
pwsh Unity/tools/sync-unity.ps1 -Target <project-name-or-path>
```

Use `-DryRun` to preview and `-Prune` to remove project-copy files deleted from the repository.
`OPENSLOPE_UNITY_PROJECTS` may point short target names at a common Unity-projects folder.

## Public and private projects

No retail content ships here. A map imported from a user-supplied disc image is local/private data and a
world built from it must not be uploaded or redistributed. Users must determine whether making and using
that image is permitted under applicable law and contractual terms.

For a distributable project, start from an authored map and stage it into a fresh destination with
`snowknife unity --public`. That command rejects retail-derived or unknown content, omits the retail
Shared pack, and requires explicit rights confirmation for user-supplied assets.
